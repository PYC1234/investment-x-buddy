# X Buddy 年报证据数据与评测手册

这套实验回答一个具体问题：用户问营收或归母净利润为什么变化时，系统能否找到同一公司、同一财年、同一指标的直接解释？工作台仍负责检索、证据展示和审批补查。这套数据流水线负责定义坏例、制作训练样例以及离线验证。

## 跟着一条坏例走

假设用户问「归母净利润为何下降」，唯一资料是「营业收入增加，主要系直营渠道拓展，归母净利润另见报表」。这条资料提到了利润，却只解释营收。按下文的标注标准，利润题的金标为空。该题及其资料随后可以生成两种训练格式，通过同一个样例 ID 关联。

1. **记录坏例。** 记录原问题、输入资料、原回答和错因。这里的错因是跨指标归因。保留原回答有助于复核坏例，并可作为偏好对的一侧。
2. **写金标。** 标注员先判断资料的公司和财年，再判断句子解释的是何种指标。如果找不到针对利润的直接说明，就给金标留空。两名人员意见有分歧时，以原文、目标指标和判定理由复核。
3. **制作 SFT 示范。** SFT 是监督微调。样例包含用户问题、可见资料与参考回答。这里的参考回答是「现有资料未直接说明归母净利润变动的原因」。
4. **制作 RM 偏好对。** RM 指奖励模型。偏好数据中的两个回答共享相同问题和资料。把上面的参考回答设为 chosen，把「利润变化归因于直营渠道拓展」设为 rejected。记录拒绝理由，方便复核者检查偏好是否由事实和任务评判标准决定。
5. **用分开的样例评测。** 同一案例家族可以在真实项目中按来源文档、公司或时间划分，以降低重复和泄漏。这个原型使用独立案例 ID 和不同的摘录，并检查规范化精确重复。部分公司与财年仍重合。

## 标注与人工验收标准

| 类别 | 判为有证据的条件 | 典型边界 |
|---|---|---|
| 标的与财年 | 摘录属于目标公司及目标报告期 | 同一家公司上一年有原因，当前年没有，保留缺口 |
| 目标指标 | 句子明确解释所问的指标 | 营收归因不可迁移到净利润，境外收入背景不可推导总营收归因 |
| 直接归因 | 原文有明确关系且因果方向可理解 | 表格数字、孤立的「原因说明」标题、待核实表述都不足以支持结论 |
| 证据不足 | 当前资料中没有合格摘录 | 如资料能支持幅度，可回答幅度。对于原因保留缺口 |
| 偏好对 | 两个答案共享同一问题和证据，有清晰可复核的优劣理由 | 有直接证据时，过度留空也属于漏答 |
| 交付验收 | 核对出处、金标、参考答案与拒选原因，记录通过或退回理由 | 导出结果默认待人工复核。通过程序校验只说明满足脚本检查 |

## 文件与复跑

从 `XBuddy/backend` 运行以下命令。评测脚本使用现有业务排序和归因规则，数据脚本不调用模型或外部服务。

```powershell
python -m app.build_annual_training_data --output-dir ../docs/annual-training-data
python -m app.evaluate_annual --output ../docs/annual-evidence-evaluation.json
python -m app.evaluate_annual --cases evals/annual_confirmation.json --output ../docs/annual-confirmation-results.json
python -m pytest tests/test_annual_data_exports.py
```

- `evals/annual_training_examples.json` 是数据制作输入。28 条构造样例包含 14 条有直接证据和 14 条缺直接证据。新增样例覆盖营收解释、利润解释、仅有数字及跨指标归因，也同时考查过度留空。
- [训练数据目录清单](annual-training-data/manifest.json) 记录产量、分层和审核状态。同目录有 28 条 SFT 示范、28 组偏好对及 28 条复核记录。两种训练格式来自同一批 28 条案例。
- `evals/annual_evidence.json` 是 11 条开发回归集，含两条公开年报案例。 `evals/annual_confirmation.json` 是 16 条构造确认用例，覆盖直接归因、倒装归因、证据缺失和范围不匹配。确认集是作者构造的诊断集。

## 对照实验与结果

固定公司和财年过滤、候选集合、金标和解释判定。分别比较通用财务关键词、按指标关键词、按问题与章节排序。三种方案共享同一个证据判定规则，所以对照主要反映排序差异。前三命中只要求正确段落被检出。受支持判定还要求系统实际选中直接解释，且没有选中金标之外的段落。MRR@3 衡量第一个正确段落的排序位置。

| 数据集 | 排序 | 前三命中（可回答题） | 受支持判定（可回答题） | 正确留空（缺证据题） | MRR@3 |
|---|---|---:|---:|---:|---:|
| 回归 | 通用关键词 | 0/4 | 0/4 | 7/7 | 0.000 |
| 回归 | 指标关键词 | 2/4 | 2/4 | 7/7 | 0.500 |
| 回归 | 按问题与章节 | 4/4 | 4/4 | 7/7 | 1.000 |
| 确认 | 通用关键词 | 2/8 | 2/8 | 8/8 | 0.250 |
| 确认 | 指标关键词 | 5/8 | 4/8 | 8/8 | 0.625 |
| 确认 | 按问题与章节 | 8/8 | 6/8 | 8/8 | 1.000 |

逐条结果见 [开发回归](annual-evidence-evaluation.json) 和 [确认集](annual-confirmation-results.json)。

## 从错误决定下一轮工作

确认集的 `check-v2-5` 和 `check-v2-6` 分别写成「新增配送网点推动了营业收入增长」和「美元负债重估使归母净利润下降」。系统都找到了这两段，但当前解释规则主要识别「指标变化，主要因为原因」的语序，两条都没有判成直接解释。这个结果把问题定位在**证据判定**，继续调整检索排序无法弥补这两条漏答。

下一轮先把倒装因果、否定因果、并列指标各抽一批真实例句。把正负例成对标注，再决定添加更窄的规则还是引入模型复核，并锁定另一批未参与修改的例句。回归时一起检查受支持判定、误引用和缺证据留空，避免通过一味放宽规则来提高召回。实际训练前还需人工质检、检查语义近重复，并加入真实授权样本。

面试复述可以沿这一条线：**把跨指标归因定义为坏例 → 写判定标准 → 从同一例生成 SFT 或偏好格式 → 做三组排序对照 → 区分检索成功与证据判定失败 → 根据失败选择下轮数据。** 当前交付是离线数据工程和评测样例，未执行模型训练，也未验证线上效果。
