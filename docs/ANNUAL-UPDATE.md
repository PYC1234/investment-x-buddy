# 年度财报更新

在工作台展开「年度财报更新」，选择 A 股代码和财年。点击「检查资料」可查看已导入年报，再点击「生成研究计划」，批准后执行。自由提问也支持「600519.SH 2024 年财报更新」或「更新 600519.SH 的 2024 年年报」；发现多公司或多个年份时需要明确范围。其他自由问题继续使用配置的通用规划器。

## 可复核的输出

- 利润表以指定年度为准，只有上一年度的完整记录可用于比较。供应商没有返回该年度时，报告展示缺口。
- 年报检索分别按营收和利润排序，优先选择直接解释变化的段落，再参考章节标题。报告单独展示当年数据、上年对照、营收解释和利润解释的状态，并引用匹配段落。
- 报告分别展示运行结果、证据质量和证据覆盖。量化字段可以按原始字段复核，管理层原文对结论的支持程度由用户判断。
- 解释缺失时，可在报告内上传对应公司和财年的文字型 PDF，最多 3 MB、350 页。较大的年报可截取章节，并填写节选前省略的页数。原 PDF 无需保存到服务端，提取的候选摘录和页码仅随本次研究保存。上传会生成补查计划，批准后才加入报告。
- 仍可使用管理员资料包补查。上传或导入资料后，已有证据会保留。

## 准备共享资料

按 [资料包 JSON Schema](research-source-bundle.schema.json) 准备一个已核对的标的资料包。年报条目的 `fiscal_year` 填报告对应财年，`as_of` 填资料日期。旧资料缺省财年时仍可用于通用检索。年度更新会筛掉这类条目。先核对股票、来源链接、PDF 页码与摘录，再使用现有导入命令。导入会替换该股票的整个包，所以应在导入前保留仍需使用的其他资料类别。

[贵州茅台样本](annual-report-samples/600519.SH.json) 和 [宁德时代样本](annual-report-samples/300750.SZ.json) 各包含一条经过本地检索验证的 2025 年报摘录。未显式导入该标的资料时，默认资料目录会使用这些随应用发布的公开样本。导入资料优先。宁德时代样本仅提供收入构成方面的信息。

从 `backend` 运行 `python -m app.import_sources 路径`。部署实例需要能读到相同的资料包，并配置真实财务数据来源。前后端发布后，以两个有资料的标的、一个历史年度和一个无资料的组合做验收。

## 试用记录

邀请几位有基础金融知识的试用者，分别用原有方式和工作台完成难度相近的任务。交换方式顺序，减少熟悉任务造成的偏差。任务完成标准为写出指定年度的营收及归母净利润、给出可复核的比较结果或缺失原因，并指出管理层原文出处或说明缺少证据。

每次记录公司、财年、使用方式、是否完成、总耗时（含复核）、来源定位错误、遗漏、返工次数及卡点。试用样本较少时报告人数、原始结果和观察。下个报告期再记录是否复用。自动化检查覆盖流程回归，用户耗时与留存由真实试用提供。

## 本地检查

- 后端 `python -m pytest tests/test_annual_update.py` 覆盖跨标的与财年、原文筛选、缺数据、补充审批和范围冲突。供应商及公告内容均为测试材料。
- 既有离线基线 `python -m app.evaluate --output 路径` 用于回归通用规划和报告流程。
- 前端 `npm run typecheck`、`npm run lint`、`npm run build`。


## 检索回归

对照使用两段已核对页码的公开年报摘录，并混入容易命中通用关键词的背景文本。按问题排序后，贵州茅台营收变化的解释能进前 3；宁德时代样本仍可展示收入背景，解释继续显示待补。该对照只验证这组样例。扩大真实问句和标注页后，可复测正确页进入前 3 的比例和直接解释命中情况。

### 离线对照实验

从 backend 执行 `python -m app.evaluate_annual --output ../docs/annual-evidence-evaluation.json`。输入为 `evals/annual_evidence.json`，包含两条来自公开年报的案例以及九条构造案例。

判定标准：标的、财年、指标均需一致。只有同一指标的直接归因原文可列入 gold。数值表、经营背景、孤立小标题、其他指标的归因均不算直接解释。没有合格摘录时应保留证据缺口。

比较双方使用相同范围过滤及解释判定。基线以通用财务关键词频次排序，候选使用业务代码里的按问题及章节排序。逐条记录前三候选、直接解释、命中、无依据摘录及正确留空。构造样例用于可复现回归，指标不代表线上质量或训练提升。
